# Modifier Module — Admin & Player Guide

The **Modifier module** is the generic system behind **reforges**, **gemstones**, and any future
attachable item bonus (traits, infusions, runes, ...). If you're looking for the old `/reforge`
command or `reforges/*.yml` config, they no longer exist — reforges are now ordinary content on top
of this engine. See `docs/modules/design/modifier.md` for internals.

---

## 1. What Changed From the Old Reforge System

| Before | Now |
|---|---|
| `/reforge list\|preview\|force\|reset` | `/modifier groups\|list\|apply\|remove` (works for reforges, gemstones, and any group) |
| `reforges/*.yml`, `stat-bonuses-by-rarity:` maps | `modifiers/groups/*.yml` + `modifiers/definitions/*.yml` |
| Reforge stones auto-generated by `/item give <id>_reforge_stone` | Ordinary static items (`items/reforge_stones.yml`) |
| `reforge_anvil` GUI (exact stone) / `reforge` GUI (random reroll) | One `modifier_anvil` GUI for everything, machine `custom_anvil` |
| `enchant/forge_costs.yml` | `rarities.yml`'s `forge_cost` property per rarity |

Existing items keep their rarity and item-type PDC exactly as before — nothing about *items*
changed, only how bonus-granting attachments (reforges/gemstones) are configured and applied.

---

## 2. Player-Facing: the Modifier Anvil

Open the Modifier Anvil GUI (`guis/modifier_anvil.yml`, machine `custom_anvil`). It has two input
slots:

- **Left** — the item you want to modify.
- **Right** — a reforge stone, a gemstone, or left **empty**, depending on what you want to do.

| You want to... | Left slot | Right slot |
|---|---|---|
| Apply a specific reforge | Your gear | The matching `<name>_reforge_stone` |
| Reroll a random reforge (costs coins, scales with rarity) | Your gear | *(empty)* |
| Socket a gemstone | Your gear | A gemstone item (e.g. `ruby_gem_2`) |
| Remove a gemstone | Your gear (must already have one socketed) | *(empty)* |

Click the anvil icon to craft. Costs (coins and/or XP levels) are shown in the recipe/item lore and
scale with the item's rarity for reforges (higher rarity = more expensive to reforge).

There is **no anvil-based reforge removal** — placing a reforged item alone always triggers a random
reroll instead (this matches the old system, which also had no in-GUI removal). An admin can strip a
reforge with `/modifier remove reforges` (see below).

## 3. Admin Command: `/modifier`

Requires `valmora.admin`.

| Command | Description |
|---|---|
| `/modifier groups` | Lists every registered modifier group and its rules (application mode, max, storage, tier source). |
| `/modifier list <group>` | Lists every modifier definition in a group (e.g. `/modifier list reforges`). |
| `/modifier apply <group> <id> [tier]` | Force-applies a modifier to the item in your main hand, bypassing recipe/cost checks. `tier` defaults to `1` (ignored for reforges — their tier is derived from the item's rarity automatically). |
| `/modifier remove <group> [id]` | Removes a modifier from the item in your main hand. Omit `id` to strip everything in that group (e.g. `/modifier remove reforges` clears whatever reforge is applied). |

Examples:
```
/modifier groups
/modifier list gemstones
/modifier apply reforges fierce
/modifier apply gemstones ruby 3
/modifier remove reforges
/modifier remove gemstones ruby
```

## 4. Content: Defining a New Modifier Group

Two folders, both scanned recursively (subfolders are for organization only):

- `plugins/Valmora/modifiers/groups/*.yml` — attachment rules.
- `plugins/Valmora/modifiers/definitions/*.yml` — the modifiers themselves.

**Important:** each top-level key in a file is one entity id directly — there is **no** wrapper key
(not `groups:\n  my_group:`, just `my_group:` at the top of the file). This matches every other
content type in Valmora (items, mobs, recipes, ...).

### 4.1 A group

```yaml
# modifiers/groups/infusions.yml
infusions:
  display:
    format: SUFFIX      # PREFIX | SUFFIX | LORE | NONE
    order: 30           # display ordering relative to other groups
  application:
    mode: MULTIPLE       # EXCLUSIVE | STACKABLE | MULTIPLE
    max: 2
    replacement: true
    removal: true
  targets:
    item_types: [SWORD, BOW]   # empty/omitted = any item type
  storage:
    mode: STACKED        # SINGLE | STACKED | INSTANCES (storage/identity only, not effects)
  tier-source: INSTANCE  # INSTANCE (default) | RARITY_RANK (see §4.3)
```

### 4.2 A modifier

```yaml
# modifiers/definitions/infusions.yml
frost_infusion:
  group: infusions
  display:
    name: "<aqua>Frost Infusion"
    suffix: " of Frost"
  targets:
    item_types: [SWORD]   # optional: narrows the group's own restriction further
  requirements:
    - "$player.skill.combat.level$ >= 10"   # ordinary script conditions
  effects:
    - type: STAT
      stat: crit_damage
      operation: ADD
      value:
        base: 5
        scaling: { type: RARITY, property: power, operation: MULTIPLY }
```

Effect `value:` accepts:
- A plain number: `value: 5`
- A rarity-scaled formula: `value: { base: 5, scaling: { type: RARITY, property: power, operation: MULTIPLY } }`
  (or `property: rank, operation: ADD, factor: <n>` for a linear-per-rank bonus)
- An arbitrary formula: `value: { expression: "10 + $item.rarity.rank$ * 5" }`

### 4.3 `tier-source: RARITY_RANK`

Set this on a group when a modifier's strength should track the *item's* rarity automatically
(like reforges), rather than being chosen when the modifier is applied (like gemstones). The
modifier then declares `tiers: 1..N` where tier `1` = the lowest rarity (`COMMON`), tier `2` the
next, and so on — see `modifiers/definitions/reforges.yml` for a full worked example with 7 tiers
(COMMON through DIVINE).

### 4.4 Making it reachable via the anvil

Add a recipe under `plugins/Valmora/modifiers/recipes/*.yml`:

```yaml
frost_infusion_scroll:
  machine: custom_anvil
  operation: APPLY_MODIFIER
  base:
    item_types: [SWORD]
  addition:
    item: frost_infusion_scroll   # a Valmora item id
    amount: 1
  modifier:
    group: infusions
    id: frost_infusion
  cost:
    coins: 500                     # flat, or rarity-scaled like a STAT effect's value:
```

Omit `addition:` entirely to make a recipe match the base item alone (used for random-reroll style
recipes — see `random_reforge` in `modifiers/recipes/reforges.yml`).

For removal:
```yaml
remove_infusion:
  machine: custom_anvil
  operation: REMOVE_MODIFIER
  base:
    item_types: [SWORD]
  modifier:
    group: infusions
    # id omitted = remove everything in the group
```

## 5. Rarities (`rarities.yml`)

Single file, `plugins/Valmora/rarities.yml`, under a top-level `rarities:` key:

```yaml
rarities:
  COMMON:
    id: common
    name: "Common"
    color: "<white>"
    rank: 0
    power: 1.0
    forge_cost: 250    # any extra numeric key is available to `scaling: { property: forge_cost }`
```

`rank` drives `tier-source: RARITY_RANK` and linear (`operation: ADD`) scaling. `power` drives the
default multiplicative scaling. Any other numeric key you add (like `forge_cost` above) becomes
usable from any `scaling: { property: <your key> }` — including in a recipe's `cost:` field, not just
modifier effects. Adding a new rarity, or rebalancing an existing one, never requires touching any
modifier or recipe file.

---

## 6. Stat Display

A modifier's stat contribution shows up merged into the item's normal "Stats" lore block — you won't
see a separate "Reforge Bonus" section. Attached gemstone/trait names (for groups with `display.
format: LORE`) show as a short "◆ <name>" line. A reforge's name shows as a prefix on the item's
display name (e.g. "**Fierce** Diamond Sword"), exactly as before.
